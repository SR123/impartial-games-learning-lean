Section 5.6, paragraph 1The complete multi-head and recurrent board-to-move maps are not AC0 families

Checked conditional theorem using named classical input Lean checks the implication from a named, unproved classical hypothesis.

1 Paper text

These are three ways around the same restricted inference problem, not three shallow algorithms for unrestricted parity. The two-frame construction changes the input and imposes a promise. The other constructions allow processing time to grow. Their complete board-to-winning-move maps cannot themselves form an AC0\AC^0AC0 family: otherwise applying either to (2,b1,…,bm)(2,b_1,\ldots,b_m)(2,b1​,…,bm​) would contradict Theorem 5.2. 2 Explain this

The three bypasses are not three shallow algorithms for parity. They are three ways around the same restricted inference problem:

  • the two-frame construction changes the input and adds a promise;
  • the rollout and recurrent constructions let the processing time grow.

The complete board-to-move maps of the last two cannot be AC0 families: otherwise, applied to the boards (2,b1,…,bm)(2,b_1,\dots,b_m)(2,b1​,…,bm​), they would compute parity, contradicting Theorem 5.2. Parallel output heads alone do not supply the rollout computation, and separators alone do not supply a recurrent scan.

The three bypasses side by side

Schematic Boxes summarise resources or group operations; they are not gates, layers or measurements.

In the restricted model, no family of polynomial-size, fixed-depth networks that reads only the current board strongly masters NIM (Theorem 5.2, which uses the named classical input on parity). Each bypass adds a different resource: an extra frame and a promise, executed rollouts, or a growing number of recurrent updates. This schematic summarises Figure 4 and Proposition 5.14; each bypass column links to a worked, exact construction.

    Input
    the current board
    Kept state
    none
    Sequential time per decision
    1 evaluation

    In the restricted model no such network family strongly masters NIM: it would give a shallow circuit for parity (using the named classical input on parity).

    Theorem on single-frame inference

  2. Two-frame restoration

    Input
    previous zero-nim-sum board and current board
    Kept state
    the restored board, kept as the next previous frame
    Sequential time per decision
    1 evaluation per decision

    Shallow selector (Boolean depth ≤ 20). Maintains a winning position once established; does not find the first winning move.

    worked restoration

  3. Multi-head rollouts

    Input
    the current board (read-only); the controller runs the B rollouts itself
    Kept state
    working board, head index, outcome bits
    Sequential time per decision
    M + 2B + 2 evaluations, M ≤ BN(2B − 1)

    Each policy step, tick and the readout is shallow; the rollouts supply the nim-sum bits.

    worked rollouts

  4. Row-wise recurrence

    Input
    the board as a stream of rows, supplied twice (board storage: once)
    Kept state
    O(B + log N) bits: summary, counter, candidate (board storage: NB + B + r bits)
    Sequential time per decision
    2N + 2 updates (board storage: N + 1)

    Each update is shallow (Boolean depth ≤ 8); the number of updates grows with N.

    worked recurrence

All three routes use shallow (AC0) components. The complete rollout and recurrent board-to-move computations are not AC0 families, given the named classical input that parity is not in AC0: otherwise they would give shallow parity circuits. Their sequential time grows with the board; that growing computation is the resource the single-frame model lacks. The two-frame route instead changes the input and relies on a promise.

How this relates to the Lean proof. Bypass.prop_bypass_interfaces packages the three constructions with their shallow components and complete winning strategies; Bypass.bypass_barriers records why the complete rollout and recurrent maps cannot themselves be AC0\mathrm{AC}^0AC0 families, assuming the named classical input that parity is not in AC0\mathrm{AC}^0AC0 (Barrier.ParityNotAC0).

What this does not show. Nothing here claims that self-play training discovers these constructions, and the restricted model is not a model of every neural network.

3 How this is formalised

Bypass.bypass_barriers: under Barrier.ParityNotAC0, (a) neither the complete finite-register multi-head map nor the complete recurrent map is computed by any AC0 formula family on the encoding family; (b) nor by any fixed-scale network family; (c) the promised two-frame map does compute parity on promised pairs, but no AC0 family produces the promised predecessor from a single frame (Barrier.no_ac0_predecessor). The individual barriers are Barrier.no_ac0_mh and Barrier.no_ac0_rec. ParityNotAC0 comes from the named input HastadNegl.
