Section 2.1, paragraph 6A one-step recurrence h_{r+1}=h_r⊕x_r accumulates parity over an arbitrarily long stream

1 Paper text

A bound on the number of preceding states consulted by one update is insufficient: even hr+1=hr⊕xrh_{r+1}=h_r\oplus x_rhr+1​=hr​⊕xr​ can accumulate parity over an arbitrarily long stream. Section 5.5 exploits precisely this distinction by allowing the number of recurrent updates to grow with the number of rows.

Generated from paper_jmlr.tex, lines 311–311.

2 Explain this

A recurrent update that looks only at its previous state is still very powerful if it is allowed to run for many steps. The update hr+1=hr⊕xrh_{r+1}=h_r\oplus x_rhr+1​=hr​⊕xr​ consults one previous state, yet after nnn steps hnh_nhn​ is the parity of all inputs, which no AC0 circuit computes.

So the right restriction for the simulation theorem is on the total number of unrolled steps TTT, not on how far back each update looks. Section 5.5 uses exactly this loophole on purpose: it lets the number of updates grow with the number of heaps.

3 How this is formalised

scan_invariant proves that folding XOR over a list of rows from an initial value gives that value XOR the nim-sum of the rows, for any length: a one-step dependency accumulates the global XOR. A single update is shallow: Recurrent.circuit_resources bounds one recurrent update by depth 4 and size 28B+828B+828B+8. The bounded-unrolling restriction under which the simulation theorem does apply is Definition A.2.
