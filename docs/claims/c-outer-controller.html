Section 5.4, paragraph 4The implemented outer controller: early-exit classifier and all-head schedule for move selection

Checked theorem Lean checks a formal statement corresponding to this claim.

1 Paper text

The checked implementation includes the outer controller: it selects a head, executes its rollout, records the outcome and either reloads the original board for the next head or halts. For classification it stops at the first outcome 1. For move selection our implementation runs all BBB heads, since an early classification decision need not supply the invariant bits required by the move readout. Each controller tick is itself an AC0\AC^0AC0 map. The original board remains available as a read-only input throughout; it is not an oracle for its nim-sum. Appendix C specifies the storage and update costs.

2 Explain this

The checked implementation is a complete machine, not just the abstract automaton. In each tick it does exactly one of: reset (load the board, select head 000); one move of the selected head's rollout; a terminal test that finds the current rollout finished; or consume a finished rollout (store its outcome, then stop or reload the original board for the next head).

Two schedules are distinguished:

  • early exit for classification: stop at the first outcome 111;
  • all heads for move selection: run every head, because choosing the move needs every invariant bit, not just "is it nonzero".

The original board is a read-only input during the whole decision. It is not an oracle for the nim-sum: the nim-sum is only obtained by executing the rollouts.

Policy πj\pi_jπj​ subtracts 2j2^j2j from the first heap of size at least 2j2^j2j, and otherwise subtracts 1 from the first nonzero heap. A rollout lets both simulated players follow πj\pi_jπj​ until no move is left; its outcome bit is the parity of the number of moves. Step through the outer controller one tick at a time: it resets, runs head 0's rollout move by move on a working copy of the board, records the outcome when the rollout ends, reloads the original board for the next head, and, in the all-head schedule, finally reads out a move. Every outcome bit here is produced by actually running the rollout; nothing is supplied from outside. Readout

σ0 = o0 = 1; σ1 = o1 ⊕ o0 = 0; σ2 = o2 ⊕ o0 = 0, so σ = 1. The readout tests every heap in parallel and takes the first that decreases:

  • heap 0: 3 ⊕ 1 = 2 smaller
  • heap 1: 4 ⊕ 1 = 5 not smaller
  • heap 2: 6 ⊕ 1 = 7 not smaller

Move: set heap 0 to 2 → (2, 4, 6), nim-sum 0.

Counting the work

  • Simulated moves M = 13 + 7 + 7 = 27 (3 heads run).
  • Evaluations M + 2B + 2 = 27 + 6 + 2 = 35: 27 move updates, 3 terminal tests, 3 outcome updates, 1 reset, 1 readout.
  • Bound on M: BN(2B − 1) = 63.
  • Each single evaluation is a shallow circuit: one policy step has Boolean depth ≤ 17 (≤ 36 threshold layers), the readout ≤ 19 (≤ 40), one controller tick ≤ 34 (≤ 70). Those bounds are per evaluation; the number of evaluations grows with the board. That no shallow family computes the complete board-to-move map is a separate statement, conditional on the named classical input that parity is not in AC0.

How this relates to the Lean proof. Each tick is one step of Shootout.ostep, with the policy step SelectCircuit.policyIdx inside the rollout registers RolloutExec.rsStep. Rollout.run_parity identifies the outcome bits with σ0\sigma_0σ0​ and σj⊕σ0\sigma_j\oplus\sigma_0σj​⊕σ0​, and Shootout.ah_counts proves that the all-head schedule takes M+2B+1M+2B+1M+2B+1 controller ticks, the reset included; with the single readout this gives M+2B+2M+2B+2M+2B+2 evaluations. The browser re-implements these steps; the agreement is checked against Lean's own evaluation of them.

What this does not show. Simulated moves and circuit evaluations are different counts: the MMM moves are part of the M+2B+2M+2B+2M+2B+2 evaluations. The depth bounds (17 per policy step, 19 for the readout, 34 per controller tick) apply to one evaluation each. The complete board-to-move computation repeats them a number of times that grows with the board. That no shallow family computes the complete map is a separate statement (Proposition 5.14 and the text after it), conditional on the named classical input that parity is not in AC0\mathrm{AC}^0AC0.

3 How this is formalised

  • Shootout.ee_spec and Shootout.ee_net: the early-exit classifier, semantically and as a threshold network, decides [nim⁡(P)≠0][\operatorname{nim}(P)\ne0][nim(P)=0].
  • Shootout.ahSel_wins: the all-head controller plus readout wins from every nonzero position against every legal opponent.
  • Shootout.ahL_counts: the executed all-head path uses one reset tick, exactly the total number of simulated legal moves, and 2B2B2B further ticks, then one readout.
  • Shootout.sh_ac0 and Shootout.sh_net: one tick (either schedule) is an AC0 formula family of depth at most 34, and a {0,1}\{0,1\}{0,1}-weight threshold network family with at most 70 layers.

These are statements about one tick; the number of ticks grows with the board (see Appendix C, paragraph 2).
