2 Explain this

The statement. A position is lost for the player to move exactly when the nim-sum is zero. From any position with nonzero nim-sum there is a move that makes it zero.

Example. (3,5,6)(3,5,6)(3,5,6) has nim-sum 000: whatever you do, the opponent can restore zero, and eventually you face the empty board. (3,4,6)(3,4,6)(3,4,6) has nim-sum 111: reducing 333 to 222 makes it zero.

Why it matters. Optimal play is "always move to nim-sum zero". The rule is short and exact, yet it requires the XOR of all heaps, a global parity computation.

How to find the move. Let s≠0s\ne0s=0 be the nim-sum and kkk its highest set bit. Some heap xxx has bit kkk set; then x⊕s<xx\oplus s<xx⊕s<x, and replacing xxx by x⊕sx\oplus sx⊕s makes the nim-sum 000.

3 How this is formalised

Semantics. Game.Win and Game.Lose are defined together, by induction, as the normal-play notions for the player to move: a position is winning if some move reaches a losing position; it is losing if every move reaches a winning position (so a terminal position is losing).

Checked statements.

  • Game.lose_iff: Lose p ↔ nimSum p = 0, for every board.
  • Game.win_iff: Win p ↔ nimSum p ≠ 0.
  • Game.exists_move_to_zero: from a nonzero nim-sum some legal move reaches nim-sum zero (the top-bit argument above, proved in Rollout.exists_decreasing_heap).
  • Game.move_from_zero: every legal move from a zero nim-sum reaches a nonzero one.

The theorem is the classical one; Lean checks it in exactly the paper's form, for any number of heaps.
