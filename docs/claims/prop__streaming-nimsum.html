Proposition 5.13A constant-depth recurrent update computes the nim-sum after N row updates and reports consecutive differences

1 Paper text

Proposition 5.13 (Sequential nim-sum accumulation) There is a recurrent Boolean update of constant depth and size O(B)O(B)O(B), implementable with fixed-scale quantised threshold gates, that computes the nim-sum of an NNN-heap position after NNN row updates. With O(B)O(B)O(B) state bits, it can also retain the previous completed nim-sum and report the XOR difference between consecutive completed positions.

2 Explain this

The update. Keep a BBB-bit accumulator sss. For each row xxx: s←s⊕xs\leftarrow s\oplus xs←s⊕x. After NNN rows, sss is the nim-sum of the position. Each update XORs two BBB-bit numbers bit by bit, a constant-depth operation.

Remembering the previous position. Keep a second register qqq and a validity bit vvv. At a separator: output sss (and q⊕sq\oplus sq⊕s if v=1v=1v=1), then set q←sq\leftarrow sq←s, s←0s\leftarrow0s←0, v←1v\leftarrow1v←1. So the machine also reports the difference between consecutive positions' nim-sums.

Example. For 3,5,6,SEP,3,4,6,SEP3,5,6,\mathtt{SEP},3,4,6,\mathtt{SEP}3,5,6,SEP,3,4,6,SEP: sss goes 3,6,03, 6, 03,6,0; at the first SEP it outputs 000; then sss goes 3,7,13,7,13,7,1; at the second SEP it outputs 111 and the difference 0⊕1=10\oplus1=10⊕1=1.

Why it matters. The update is shallow; the computation as a whole takes NNN updates. The bypass works by letting the number of updates grow, which the simulation theorem forbids for fixed-latency models.

Row-wise recurrence: registers, separators and replay

Exact construction trace Every value is computed from the construction’s definitions for the example shown.

The board arrives as a stream of rows, one heap per token, with separators (SEP) between positions and a reset at the start of a game. Step through the replay controller: in scan mode it XORs each row into the accumulator; the first separator outputs the summary, stores it and switches to replay mode; during replay the same rows arrive again and each is tested against the stored summary, keeping the first cancelling candidate and a fallback; the second separator outputs the move. The board-storage variant instead writes the rows into memory and chooses the move at its single separator. In the replay controller a separator clears the accumulator and keeps the summary of the position just completed, with its validity bit; an extra separator is read as an empty position, whose summary is 0. Only a reset returns every register, validity included, to its initial value. The board-storage separator clears its accumulator and pointer and keeps the stored board. The third protocol shows the summary mechanism of Proposition 5.13 alone: it reports summaries and differences but chooses no move.

Counting the work

  • Each position of 3 heaps takes N + 1 = 4 updates: its rows and a separator. The state is (s, q, v): 2B + 1 = 7 bits.
  • The summary alone does not choose a move: that needs the rows again (replay) or a stored board.
  • Each output bit of one update is a formula of depth ≤ 4. The number of sequential updates grows with N. That no shallow family computes the complete board-to-move map is a separate statement, conditional on the named classical input that parity is not in AC0.

How this relates to the Lean proof. Each update is one step of Controller.cstep (replay) or BoardStore.bsStep (board storage) on the token streams Controller.dtoks and BoardStore.btoks. The whole-game theorems WholeGame.replay_wins and BoardStore.bits_store_wins prove that, from every board with nonzero nim-sum, iterating these updates wins against every legal opponent. The summary mechanism is Recurrent.step. The comparison of decision-time boards with the post-move board is Bypass.diff_with_postMove and Bypass.diff_decision_only.

What this does not show. Each single update is shallow; the number of updates per decision (2N+22N+22N+2, or N+1N+1N+1 with board storage) grows with the board. That no shallow family computes the complete board-to-move map is a separate statement, conditional on the named classical input that parity is not in AC0\mathrm{AC}^0AC0. The edge cases (an extra separator, a reset) lie outside the protocol streams that the theorems quantify over; the update rule is simply applied. The recurrent strategies are proved in their own stateful game semantics; connecting them to the later history model of weak mastery is a separate adapter that has not been built (coverage record). No recurrent network was trained.

3 How this is formalised

  • Recurrent.fold_invariant: from any state with empty accumulator, for any finite sequence of positions, the ttt-th output is (σ(Pt),Δ)(\sigma(P_t), \Delta)(σ(Pt​),Δ) with Δ=σ(Pt−1)⊕σ(Pt)\Delta=\sigma(P_{t-1})\oplus\sigma(P_t)Δ=σ(Pt−1​)⊕σ(Pt​) for t≥2t\ge2t≥2 (and determined by the starting state for t=1t=1t=1).
  • Recurrent.stream_reports_delta: from the initial state the first output has no difference and the second reports nim⁡(Q)⊕nim⁡(Q′)\operatorname{nim}(Q)\oplus\operatorname{nim}(Q')nim(Q)⊕nim(Q′).
  • Recurrent.circuit_update and Recurrent.circuit_step_correct: 2B+12B+12B+1 state bits suffice and explicit per-bit circuits compute the update.
  • Recurrent.circuit_resources: depth at most 444, total size at most 28B+828B+828B+8.
  • Recurrent.xorNet_correct: a fixed-scale threshold realisation of one XOR bit update.
