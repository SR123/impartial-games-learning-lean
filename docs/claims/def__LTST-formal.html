Definition A.3Gate-realised attention-style model: every operation implemented in the permitted gates

1 Paper text

Definition A.3 (Gate-realised attention-style model) Fix a time window T∈NT\in\NT∈N. A fixed-scale quantised LTST\LTSTLTST model processes a sequence (xt−T+1,…,xt)(x_{t-T+1},\dots,x_t)(xt−T+1​,…,xt​) by:

  • computing short-term and long-term attention scores using fixed-scale quantised parameters in QW,D\Qset_{W,D}QW,D​,

  • combining attended summaries through a constant number of layers of fixed-scale quantised threshold computations,

  • producing outputs ot∈{0,1}ko_t\in\bits^kot​∈{0,1}k.

Every score computation, input-dependent coefficient selection, encoding and value aggregation is required to have a polynomial-size, constant-depth implementation in the Boolean literal-threshold gates of Definition A.1. Intermediate state is Boolean, and total unrolling is bounded as in Definition A.2. Under these explicit implementation assumptions, the simulation theorem applies by composition. Merely requiring parameters or coefficients to lie in a finite set is insufficient. This extension makes no claim about standard softmax attention without such a reduction.

2 Explain this

An "attention-style" model is admitted only in a gate-realised form: every score computation, input-dependent coefficient selection, encoding and aggregation must itself be a polynomial-size, constant-depth network of the permitted literal-threshold gates, with Boolean intermediate states and bounded total unrolling. Then the simulation theorem applies by composition.

Caveat: merely restricting parameters or coefficients to a finite set is not enough, and nothing is claimed about standard softmax attention.

3 How this is formalised

Windows.staged_ac0: a model given as a list of KKK stages (Windows.runStages), each a valid network of at most LLL layers with bounded widths, is computed by formulas of depth at most 3KL3KL3KL and explicit size, reading only the inputs. Why a finite coefficient set alone is insufficient: Remark 2.2 (model scope).
